# Hay Day Farm ETL Pipeline

**ETL-пайплайн** (Extract-Transform-Load) для збору, очищення та аналітики ігрових даних мобільної гри *Hay Day*. 

Проєкт реалізовано за допомогою двох послідовних модулів на Python:
1. **Збір та збереження (Extract & Load):** Перший скрипт зчитує сирі CSV-файли та без змін імпортує їх у буферну схему `raw` (Staging-шар) бази даних.
2. **Трансформація та завантаження (Transform & Load):** Другий скрипт виступає оркестратором: він зчитує сирі дані, очищує та трансформує їх, після чого записує у кінцеву аналітичну схему `dbo`.

*Пайплайн повністю підготовлено для автоматизації та запуску за розкладом (через Windows Task Scheduler).*

---

## Архітектура та Технологічний стек

Проєкт побудований за двошаровою архітектурою сховища даних:
1. **Staging Layer (Схема `raw`):** Зона для первинного завантаження сирих даних "як є".
2. **Core Warehouse Layer (Схема `dbo`):** Очищені та структуровані дані, змодельовані за класичною схемою **"Зірка" (Star Schema)**, яка складається з таблиць довідників (`dimensions`) та фактів (`facts`).

**Технологічний стек:**
* **СУБД:** Microsoft SQL Server (зберігання даних та зв'язків схеми "Зірка")
* **Мова розробки:** Python 3
* **Зовнішні бібліотеки (сторонні залежності):**
  * `pandas` — для очищення, фільтрації та структурування даних у пам'яті.
  * `SQLAlchemy` — для зручного підключення до бази даних та виконання транзакцій.
  * `python-dotenv` — для безпечного зчитування конфігураційних змінних із файлу `.env`.
* **Вбудовані модулі Python (Standard Library):**
  * `logging` — для ведення детального журналу роботи пайплайну в `pipeline.log`.
  * `json` — для парсингу конфігураційних файлів (`pipeline_config.json`, `raw_etl_config.json`).
  * `pathlib`, `os` — для гнучкої та кросплатформної роботи з файловими шляхами в проєкті.
  * `sys` — для отримання аргументів командного рядка (CLI) та керування режимами запуску пайплайну.
* **Автоматизація:** Windows Task Scheduler (Планувальник завдань)

## Деталі реалізації пайплайну (Pipeline Architecture)

Пайплайн складається з двох основних модулів, які забезпечують інджестіон та подальшу трансформацію даних:

### 1. Модуль інджестіону (`raw_etl_pipeline.py`)
Відповідає виключно за зчитування первинних CSV-файлів та завантаження їх без змін у сиру схему `raw` моєї БД.
* **Основна функція:** `load_raw_data()`
* **Конфігурація:** Керується за допомогою конфіг-файлу `raw_etl_config.json`.

### 2. Модуль оркестрації та трансформації (`main_pipeline.py`)
Головний скрипт, який зчитує сирі дані зі схеми `raw`, трансформує їх та завантажує у кінцеву аналітичну схему `dbo`. Логіка реалізована в класі `Hay_Day_ETL_pipeline` за допомогою 5 ключових методів, розділених за типом обробки таблиць:

#### Обробка статичних (базових) таблиць:
Логіку обробки цих таблиць жорстко прописано в коді програми для стабільності системи:
* `transform_base_dimension()` — обробка **головних довідників** (нові для цієї категорії не передбачені).
* `transform_game_entities()` — обробка базових **загальних довідників**.
* `transform_farm_facts()` — обробка базових **таблиць фактів**.

#### Динамічне масштабування (обробка нових таблиць):
Для того, щоб систему можна було легко розширювати без переписування коду, додавання нових таблиць реалізовано через конфігураційні файли (зокрема `pipeline_config.json`):
* `load_new_demensions_config()` — автоматично обробляє та створює **нові довідники** на основі конфігу.
* `load_new_facts_config()` — динамічно створює та наповнює **нові таблиці фактів** за допомогою конфігу.

## Ключові особливості 

* **Гнучке масштабування:** Можливість додавання нових таблиць фактів та вимірів через JSON-конфіги без втручання в основний код Python.
* **Роздільна оркестрація (CLI):** Пайплайн підтримує запуск у різних режимах за допомогою аргументів командного рядка:
  * `python main.py -m dimensions` — оновлення лише довідників.
  * `python main.py -m facts` — інкрементальне оновлення таблиць фактів.
  * `python main.py -m all` — повний цикл ELT.
* **Безпека (Security):** Параметри підключення до бази даних повністю ізольовані в змінних оточення (`.env`).
* **Стійкість до помилок (Fault Tolerance):** Реалізовано обробку винятків на рівні Python-скриптів із логуванням усіх подій у файл `pipeline.log`.
